# Task Completion Report

## Outcome

Completed TASK-0020: Automo now uses Poetry Core rather than setuptools for PEP 517 packaging and has a PPW-style first-time developer bootstrap that installs/pre-provisions the clone-local pre-commit hook.

## Changes made

- `pyproject.toml`: Poetry Core backend, static canonical `project.version`, Poetry `src/` package declaration, build/Poetry Core dev dependencies.
- `src/automo/_version.py`: distribution metadata lookup with source-checkout `pyproject.toml` fallback; no duplicate version literal.
- `scripts/health_gate.py`: generic PEP 517 `python -m build` wheel/sdist path; removed setuptools backend import and egg-info cleanup workaround.
- `scripts/init_dev.py`: PPW-style dev sync + Git hook bootstrap.
- `.github/workflows/publish-pypi.yml`: release tag version check reads canonical `project.version`.
- `README.md`, `CONTRIBUTING.md`, `docs/PROJECT-SKELETON.md`, `.agent/command-reference.md`: corrected packaging/bootstrap workflow.
- `MANIFEST.in`: removed because it was setuptools-specific.

## Design decisions

- Use Poetry Core as build backend, but retain PEP 621 `[project]` metadata rather than copying PPW's now-deprecated Poetry-only metadata fields.
- Keep uv as development/test environment manager; Poetry Core is packaging infrastructure, not a required developer CLI.
- Keep hook installation in explicit repository bootstrap, never in ordinary `pip install automo`.
