# Task Completion Report

## Outcome

Completed. Automo now follows a PPW-style portable tox model: one active local Python, with the full supported-version matrix delegated to GitHub.

## Changes made

- Changed the pre-commit unit-test hook to `poetry run tox -e py`.
- Added `[gh-actions]` mappings for Python 3.11, 3.12, and 3.13.
- Restored a GitHub compatibility matrix that runs `poetry run tox` once per supported Python.
- Kept the GitHub quality job as the same full-repository pre-commit gate used locally.
- Updated public/developer/release documentation for Conda and plain virtualenv portability.

## Behaviour added or corrected

- A developer needs only one supported active Python locally.
- Tox creates `.tox/py` from that active interpreter.
- GitHub proves Python 3.11/3.12/3.13 compatibility through separate jobs.
- No tox-conda plugin or Conda-specific path is part of the repository contract.

## Tests added or changed

- Release-contract tests now pin the active-Python pre-commit tox command, tox-gh-actions mappings, and GitHub matrix.

## Documentation updated

- README, CONTRIBUTING, project skeleton, and publishing guidance now describe the portable local/CI split.

## Design decisions

- Follow PPW's separation between ordinary local development and GitHub's supported-Python matrix instead of forcing every developer machine to expose all supported interpreters.

## Known limitations

- Connected GitHub and Poetry package smoke evidence is still required before M13 can close.

## Remaining TODOs

## Risks and blockers

- A host environment containing incompatible third-party tox plugins can still contaminate tox itself; clean project environments should not install `tox-conda`. This is not an Automo dependency or workflow requirement.
