## Outcome

Completed the GetDone dev 1.1.2 workflow-contract migration and unified GetDone-like MR command experience without adding a mandatory GetDone dependency.

## Changes made

- Added `src/getdone_mr/ux.py` for project status, planning, diagnostics, validation, initialization, and legal-transition routing.

## Behaviour added or corrected

- Users can navigate normal work with `init`, `doctor`, `status`, `plan`, `run`, and `validate`.
- `run` performs exactly one committed legal transition and refuses to repeat completed temporal evidence.
- Advanced primitives are discoverable under `experiment`, `features`, `findings`, `stability`, `promotion`, `capability`, and `integration` groups.
- Existing low-level command names remain hidden compatibility aliases.
- Optional GetDone validation is invoked when the package is installed; standalone operation warns rather than failing when it is absent.

## Design decisions

- The project-oriented CLI is a navigation layer over deterministic primitives, not an autonomous gate-skipping engine.
- GetDone installation alone never enables delegated capability execution.
- Migration preserves project-owned research history and modifies only contract/control records required for compatibility.

## Known limitations

- `getdone-mr init` creates the standalone MR skeleton but does not generate a complete research objective or experiment automatically.
- The high-level `run` router currently knows the committed temporal-stability protocol; other evaluation protocols remain available through advanced commands until explicit transitions are registered.
- Cross-platform wheel smoke testing remains outstanding.
