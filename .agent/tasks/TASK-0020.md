# Task: Restore PPW-derived Poetry packaging and developer bootstrap

## Objective

Restore the intended PPW-derived packaging/developer foundation without changing Automo research functionality: Poetry Core builds the package, `pyproject.toml` owns the version, and first-time developer bootstrap installs the Git pre-commit hook automatically.

## Specification

- Replace the setuptools PEP 517 backend with `poetry.core.masonry.api`.
- Keep standard `[project]` metadata for modern Poetry/uv interoperability and keep `src/automo/` layout via `[tool.poetry].packages`.
- Make `[project].version` the sole literal package version; runtime version access reads distribution metadata with a source-checkout fallback to `pyproject.toml`.
- Remove setuptools-specific build/source artifacts and health-gate logic.
- Add a one-command PPW-style developer bootstrap that runs `uv sync --extra dev` then clone-local `pre-commit install --install-hooks`.
- Keep the ChatGPT/sandbox `uv run ...` path separate from the normal developer workflow.
- Keep GitHub Actions pre-commit execution direct and independent from developer hook installation.
- Do not add model-research features, mypy adoption, or a Poetry CLI runtime requirement.

## Ordered plan

1. Convert package build metadata and version ownership to Poetry Core.
2. Convert health/release scripts and publishing version checks away from setuptools internals.
3. Add and test the developer bootstrap.
4. Update contributor/project docs and active M13 records without changing controlled record structure.
5. Run local tests/source/compile validation and attempt the Poetry Core build; leave connected build/CI evidence to the existing M13 next step when dependencies cannot be provisioned locally.
