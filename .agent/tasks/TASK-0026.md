# Task: Restore PPW-style portable tox workflow

## Objective

Make the canonical developer workflow work unchanged in either a Conda environment or a plain Python virtual environment without requiring all supported Python versions locally, while retaining Python 3.11/3.12/3.13 compatibility coverage in GitHub.

## Specification

- Local pre-commit must run unit tests through tox using only the active supported Python.
- Tox must create its local isolated environment under `.tox/py`.
- GitHub must use a Python 3.11/3.12/3.13 matrix and CI-only `tox-gh-actions`, following PPW's CI pattern.
- Do not use `tox-conda`, Conda-specific paths, or multiple local interpreter requirements.
- Keep Poetry as the package/dependency manager and pre-commit as the local quality gate.

## Ordered plan

1. Compare Automo's tox/CI behavior with PPW's generated tox and GitHub workflow.
2. Change the pre-commit tox hook to `tox -e py`.
3. Add `tox-gh-actions` mapping for 3.11/3.12/3.13 and restore a GitHub compatibility matrix.
4. Update developer/release documentation and regression contracts.
5. Run focused/full tests, source/compile checks, and GetDone validation.

## Acceptance criteria

- [x] AC-001: local pre-commit uses `poetry run tox -e py`.
- [x] AC-002: no local requirement exists for Python 3.11, 3.12, and 3.13 simultaneously.
- [x] AC-003: GitHub has a 3.11/3.12/3.13 matrix running tox with `tox-gh-actions`.
- [x] AC-004: repository contains no tox-conda or Conda-specific interpreter-path contract.
- [x] AC-005: docs state both Conda and plain virtualenv workflows are supported.

## Outcome

Completed. Local testing now follows the active interpreter while CI owns the supported-version matrix.
