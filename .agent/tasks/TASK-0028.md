# Task: Simplify developer bootstrap to PPW model

## Objective

Remove the layered Conda/venv/Poetry bootstrap assumptions and restore PPW's simple contributor setup while preserving Automo's active-Python local tox hook and GitHub compatibility matrix.

## Specification

- Bootstrap from the currently selected Python, whether supplied by Conda, a venv, or plain Python.
- Follow PPW order: install pre-commit, run standard `pre-commit install`, install Poetry, then run `poetry install --with dev`.
- Do not require Poetry to exist before bootstrap.
- Do not require developers to manually create or activate `.venv`; Poetry owns its project environment.
- Keep local unit tests in pre-commit through `poetry run tox -e py`.
- Keep GitHub responsible for Python 3.11/3.12/3.13 compatibility.

## Acceptance criteria

- [x] AC-001: bootstrap installs pre-commit with the current Python and runs standard `pre-commit install`.
- [x] AC-002: bootstrap installs Poetry with the current Python and then runs `poetry install --with dev`.
- [x] AC-003: docs do not require manual `.venv` creation/activation or Conda-specific setup.
- [x] AC-004: local pre-commit tox hook remains `poetry run tox -e py`.
- [x] AC-005: GitHub compatibility remains a Python 3.11/3.12/3.13 tox matrix.
- [x] AC-006: focused and full repository tests pass.

## Outcome

Completed. Automo now uses the PPW bootstrap model without layered environment orchestration.
